# Phase 4a — VM check of install and uninstall (controller)

- **What it checks:** spec §8's phase 4 criterion, the install and uninstall half (update is 4b's). On VM-A, VM-B and VM-C the installer installs for the user, starts the app, and makes the two Start-menu shortcuts and the Path entry. `cmdstudio doctor` typed in cmd prints before the prompt returns and gives cmd its exit code. The uninstaller puts AutoRun, the user's Path, the font registrations and files, and Windows Terminal's settings back byte for byte. It keeps the themes unless the box is ticked, and leaves no install folder, shortcut or uninstall key.
- **The build:** CI's artifact `cmdstudio-installer` of this branch's head (ci.yml's `app` job): `CMD Studio_<version>_x64-setup.exe` and `SHA256SUMS.txt`. **One download per check**, with the founder's explicit yes first, into one folder that every VM is filled from: `gh run list --workflow ci.yml --branch phase4 --limit 5 --json databaseId,headSha,status,conclusion`, then `gh run download <run id> --name cmdstudio-installer --dir <scratchpad>\p4a-installer`. Then `git diff --stat <headSha> HEAD -- app crates presets schema scripts Cargo.toml Cargo.lock .github` must print nothing. Nothing is downloaded again for VM-B, VM-C or a fresh `Start-CleanVm`: `Install-Phase4Setup` copies from that folder. Record the commit and the run id below.
- **VMs** (`spikes/vm/README.md`; each from `clean`): VM-A `cmdstudio-win11` (`tester`), VM-B `cmdstudio-win10` (`tester`, no Windows Terminal), VM-C `cmdstudio-th` (the Thai user with a space).
- **Setup (once per host session):** Windows PowerShell 5.1 on the host, outside any sandbox, in an unlocked session, from the repo root: `. .\spikes\vm\vm.ps1`, `. .\docs\spikes\phase3-vm-check\helpers.ps1`, `. .\docs\spikes\phase4-install\helpers.ps1`; `$artifact = '<scratchpad>\p4a-installer'`.
- **Setup (per VM, and again after every `Start-CleanVm`):** `$vm` and `$u` as `docs/spikes/phase3-vm-check/protocol.md` sets them (VM-C's `$u` in code points). Then:
  1. `Start-CleanVm $vm $u`.
  2. `Install-Phase4Setup $vm $u $artifact -MarkOfTheWeb` on VM-A and VM-C; on VM-B the same without `-MarkOfTheWeb`. It prints `same file: True` and one line of `SHA256SUMS.txt` with the hash. The mark makes the copy look like a browser download, so that SmartScreen judges it as a person's download would be judged. Without the mark, a file copied in by guestcontrol never meets SmartScreen.
  3. `Invoke-GuestDesktop $vm "$($P4.Guest)\guard.test.ps1" '' $u` must end with `guest guards: 45/45 checks pass`.
- **The VM commands of this check** are the functions of this folder's `helpers.ps1`. Each one runs `spikes/vm/guest/install-check.ps1` on the user's desktop (`Invoke-GuestDesktop`, where HKCU and the environment are the user's), unless it says it is console-free.

  | Function | What it does |
  |---|---|
  | `Get-Phase4Snapshot $vm <label> $u` | `-Snapshot <label>`: AutoRun, the Path, the font registrations and files, WT's `settings.json`, the Start-menu folder, the desktop shortcut, the uninstall key, Tauri's `HKCU\Software\<publisher>\CMD Studio`, the install folder, the data folder and its `themes\`. Any lower-case label; `Compare-Phase4` reads `before` and `after`. |
  | `Compare-Phase4 $vm ThemesKept` or `ThemesGone`, `$u` | `-Compare` with the same switch |
  | `Get-Phase4Cli $vm $u` | `-Cli` |
  | `Start-Phase4Install $vm $u [-Silent]` | `-Install` or `-InstallSilent` with `-Setup $P4.Setup`. The script picks the one `*-setup.exe` there, so the name with its spaces never passes through a command line. Silent is `/S` with `Start-Process -Wait`; a mark of the web is removed first, because Windows' "Open File" warning would stop a silent run. Interactive returns at once. |
  | `Start-Phase4Uninstall $vm $u [-Silent]` | `-Uninstall` or `-UninstallSilent` (the installed `uninstall.exe`, `/S`, waited for) |
  | `Start-Phase4FontHold`, `Get-Phase4FontHold` (console-free), `Stop-Phase4FontHold` | `-HoldFont` (the installed font file held open for 10 minutes by a process of its own), whether that process still runs, and `-ReleaseFont` (that process ended) |
  | `Invoke-Phase4CleanupAll $vm $u` | `-CleanupAll`: the installed `cmdstudio.com --cleanup --remove-themes` and `EXIT=<code>` |
  | `Get-Phase4Installed $vm $u` (console-free) | the install folder's entries, and `running: <pid>` for each `cmdstudio` process |
  | `Close-Phase4App $vm $u` | the app closed with `CloseMainWindow` on the desktop, ended only if it does not answer in 10 s; the lines say which happened |
  | `Close-Phase4Cmd $vm $u` (console-free) | every cmd, Windows Terminal and OpenConsole ended |
  | `Invoke-Phase4Control $vm '<name>' $u` | presses, ticks or selects the control of that name in any top-level window (installer, uninstaller, SmartScreen) through UI Automation. Best effort; the keys and a screenshot are the fallback. |

- **What Task 3's installer does (appendix B 2026-11-04, `app/src-tauri/windows/hooks.nsh`), which the steps check:**
  - The uninstaller's hook runs Tauri's `CheckIfAppIsRunning` first, then `--cleanup` through `cmdstudio.com` (with `--remove-themes` when "Delete the application data" is ticked), then `--remove-from-path`.
  - The deletes of `cmdstudio.com` and of the Recovery shortcut are in POSTUNINSTALL, after Tauri's own deletes.
  - A failed cleanup keeps the data folder: the hook un-ticks the box and says so in a box.
  - A newer version installed by hand over an old one runs the old uninstaller without `/UPDATE` (`$UpdateMode = 0`). That is the old uninstaller's full cleanup. Tauri's "already installed" page offers it ("Uninstall before installing" for a newer version, "Uninstall CMD Studio" for the same one). A silent `/S` install shows no page, so it runs no old uninstaller.
- **Rules:**
  - Nothing here runs on the dev PC, not even as a dry run. Every guest script refuses a machine whose name does not start with `CMDSTUDIO-`.
  - cmd runs without `/d` inside the VMs.
  - Do not repair a VM: record the step and go on.
  - The installer and the uninstaller are driven with `Send-Key` and `Invoke-Phase4Control`, with a `Save-Shot` after every page. Press Enter only on a window the last screenshot shows: the uninstaller closes by itself when it is done.
  - Guest paths are written as `C:\Users\$u\…` on the host, never `$env:…`, which would expand on the host PC.
  - On VM-C, press `Send-Key $vm WinSpace` before any `Send-Run`, `Send-Text` or `Get-GuestAutoRun`, and check that the tray shows ENG.
  - The words are `en.ts`'s, and `th.ts`'s on VM-C once Thai is chosen in the wizard, as phase 3's protocol says. The installer's are Tauri's English NSIS texts, and the boxes' are the hooks' texts in `app/src-tauri/windows/hooks.nsh`.
- **How results are judged:** by `install-check.ps1`'s printed lines (`SAME`, `GONE`, `VERDICT: PASS`), by the `-Cli` output's order (`where`, the doctor lines, `EXIT=<n>`, `PROMPT-RETURNED`), and by pixel counts or words on a screenshot where nothing prints (the installer's pages, SmartScreen, the typed command).
- **Date / commit / run:** written by the controller.
