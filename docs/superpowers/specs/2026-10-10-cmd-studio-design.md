## 0. Implementation Gate

ก่อนเขียนโค้ดที่ใช้สิ่งใดในตารางนี้ ผู้ implement ต้องทำตามนี้:
1. เปิดซอร์สหรือเอกสารของสิ่งนั้น
2. อ่าน signature หรือรูปร่างข้อมูลให้ครบทุกส่วน ไม่ใช่แค่เช็กว่ามีชื่อนี้อยู่
3. ยืนยันว่าตรงกับที่สเปกใช้ ถ้าไม่ตรง **ให้หยุดแล้วแจ้ง founder** ห้ามเขียนโค้ดข้ามความขัดแย้งไป
4. ถ้าของจริงต่างจากสเปก ให้ถือของจริงเป็นหลัก แล้วแก้สเปกตาม

## 1. เป้าหมาย ขอบเขต และเกณฑ์สำเร็จ

**เป้าหมาย:** ทำโปรแกรมบน Windows ที่ให้ผู้ใช้ทั่วไป ไม่ใช่แค่ dev แต่งหน้าตา cmd ได้โดยไม่ต้องพิมพ์คำสั่ง มีธีมสำเร็จรูปให้เลือกและปรับเองได้อิสระ แจกฟรีแบบโอเพนซอร์ส

**สิ่งที่อยู่ใน v1**
- **ระบบปฏิบัติการ:**
  - Windows 11 ใช้ได้ครบทุกอย่าง
  - Windows 10 รุ่น 2004 (build 19041) ขึ้นไป ซึ่งเป็นรุ่นต่ำสุดที่ Windows Terminal รองรับ (G18 ✅) ได้ prompt และกล่องต้อนรับ ✅ (ทดสอบบน VM Windows 10 22H2 ที่เปิด cmd เป็น conhost) แต่หน้าต่าง cmd แบบเก่าที่ไม่ได้เปิดใน Windows Terminal จะไม่ได้สีพื้น
  - ถ้าเครื่องไม่มี Windows Terminal โปรแกรมจะพาไปติดตั้ง
  - รองรับเฉพาะเครื่อง x64 ถ้าเป็นเครื่อง ARM64 ตัวติดตั้งจะแจ้งว่ายังไม่รองรับ
- **ธีม:**
  - มี preset 12 แบบ ทั้งโทนมืดและโทนสว่าง
  - ทำสำเนาไปแก้ได้ทุกอย่าง และบันทึกไว้ได้หลายธีม
  - นำเข้าและส่งออกเป็นไฟล์ `.cmdtheme`
- **ผู้ใช้ทั่วไป:**
  - ไม่ต้องพิมพ์คำสั่ง และไม่ต้องรู้จัก Oh My Posh หรือ Clink
  - ไม่ต้องใช้สิทธิ์ admin
  - หน้าโปรแกรมของแอปมีภาษาไทยและอังกฤษ เลือกให้ตามภาษาของเครื่อง ส่วนทุกอย่างที่ CMD Studio เขียนลงหน้าต่าง cmd เป็นภาษาอังกฤษเสมอ (ภาคผนวก B 2026-10-13)
- **ความปลอดภัย:**
  - ถ่ายจุดย้อนกลับก่อนใช้ธีมทุกครั้ง และมีปุ่ม "ย้อนทุกอย่าง"
  - ถอนโปรแกรมแล้วเครื่องกลับเป็นเหมือนเดิม
- **การแจกจ่าย:**
  - ตัวติดตั้งไฟล์เดียวที่รวม Oh My Posh, Clink และฟอนต์ไว้ในตัว
  - แจกผ่าน GitHub Releases และ winget
  - โปรแกรมอัปเดตตัวเองได้

### 2.2 บทเรียนจากต้นแบบทำมือ (ห้ามพลาดซ้ำ)
1. **แอปที่แพ็กเป็น MSIX ถูกแยกพื้นที่:** สิ่งที่แอปแบบนี้เขียนลง `%LOCALAPPDATA%` (นอกโฟลเดอร์ `Packages`) และ `HKCU` โปรแกรมอื่นมองไม่เห็น CMD Studio จึงต้องเป็น exe ธรรมดา ✅ (เจอจริงกับแอป Claude)
2. **`commandline` ของโปรไฟล์ cmd ใน WT ต้องเปล่า** ถ้ามี argument ต่อท้าย หน้าต่าง cmd ที่เปิดจากนอก WT จะไม่ได้สีของโปรไฟล์ ✅ (ส่วนที่มี argument) / ✅ (ส่วนที่ commandline เปล่า, G7 บน VM Windows 11) ข้อยกเว้นคือโหมด "เฉพาะใน Windows Terminal" ตาม §5.4
3. **กล่องต้อนรับต้องพิมพ์ใน `clink.oninject`** ไม่ใช่ `clink.onbeginedit` เพราะแบบหลังทำให้ prompt แรกย่อไม่ได้ และท้ายกล่องห้ามเป็นบรรทัดว่างเปล่า ต้องใช้บรรทัดที่มีช่องว่าง 1 ตัวแทน ✅
4. **สคริปต์ Lua ถูกโหลดตอนรัน `clink set` ด้วย** สคริปต์จึงห้ามมี side effect ตอนโหลด ทุกอย่างต้องผูกกับ event ✅
5. **DLL ของ Clink ถูกโหลดค้างอยู่ใน cmd ทุกหน้าต่างที่เปิดอยู่** จึงเขียนทับตอนอัปเดตไม่ได้ ทางแก้คือแยกโฟลเดอร์ runtime ตามเวอร์ชัน (ข้อนี้มาจากเหตุผลเชิงทฤษฎี ⬜ ยังไม่ได้ลองเขียนทับจริง)
6. **ถอนโปรแกรมต้องปิด AutoRun ก่อนลบไฟล์** ไม่อย่างนั้น cmd ทุกหน้าต่างจะขึ้น error
7. **ห้ามทดสอบ GUI ด้วยการแย่งโฟกัสหรือส่งคีย์บนเครื่องที่ผู้ใช้กำลังใช้อยู่** ต้นแบบเคยไปย่อหน้าต่างเกมของผู้ใช้มาแล้ว ให้ทดสอบใน VM หรือ CI แทน
8. **Clink 1.9.34 inject ไม่ได้ถ้าไฟล์ของมันอยู่ใต้ path ที่มีอักษรไทย** ทั้งบน Windows ภาษาไทยและภาษาอังกฤษ และ cmd ทุกหน้าต่างจะขึ้นข้อความ error ของ Clink ห้ามเรียก Clink ด้วย path ที่มีอักษรนอก ASCII ให้เรียกผ่าน `<clink-launch>` ตาม §5.4 เสมอ (G19 ❌ เจอบน VM 2026-10-11)
9. **ห้ามสร้าง registry key ใหม่ทับ key ที่มีอยู่** เช่น `New-Item -Force` ใน PowerShell เพราะจะลบทุกค่าและ subkey ใน key นั้น ตัวเชื่อม AutoRun ต้องเปิด key เดิมแล้วแก้แค่ค่า `AutoRun` ✅ (ทดสอบแล้ว 2026-10-10 สคริปต์ probe ตัวแรกพลาดข้อนี้)

### 3.3 รูปแบบไฟล์ `.cmdtheme` v1 (เป็นสัญญาสาธารณะ)

```json
{
  "schemaVersion": 1,
  "id": "2f0c8f0e-6a8e-4b7e-9a4f-3f1f0b9c1d2e",
  "name": "Terracotta ของฉัน",
  "author": "",
  "tone": "dark",
  "simple": { "accent": "#d97757", "tint": 0.10 },
  "colors": {
    "background": "#1f1e1d",
    "foreground": "#faf9f5",
    "cursor": "#d97757",
    "selection": "#4a4845",
    "accent": "#d97757",
    "muted": "#8a8780",
    "frame": "#5f5d58",
    "ansi": [
      "#3a3936", "#e5736a", "#8fbf7f", "#e3b66b", "#7fa7d9", "#b79bdb", "#7fc1b8", "#d8d6cf",
      "#8a8780", "#f0907f", "#a8d196", "#eecb8a", "#9bbde8", "#cbb4e8", "#9dd3cb", "#faf9f5"
    ]
  },
  "terminal": {
    "font": "Cascadia Mono",
    "fontSize": 12,
    "cursorShape": "filledBox",
    "opacity": 96,
    "acrylic": true,
    "padding": [14, 10]
  },
  "prompt": {
    "layout": "box",
    "segments": ["path", "git", "time"],
    "transient": true
  },
  "banner": {
    "enabled": true,
    "title": "Welcome back, {user}!",
    "lines": ["cwd: {cwd}", "{date} · {time} · {host}"],
    "tips": true,
    "clearLogo": true
  }
}
```

กติกาของแต่ละช่อง:
- **`schemaVersion`:** จำนวนเต็มตั้งแต่ 1 ขึ้นไป
  - ถ้าเลขสูงกว่าที่โปรแกรมรู้จัก ให้ปฏิเสธพร้อมข้อความ "ไฟล์นี้มาจาก CMD Studio รุ่นใหม่กว่า กรุณาอัปเดตโปรแกรม" (`E_THEME_NEWER_SCHEMA`)
  - ถ้าเลขต่ำกว่า ให้แปลงขึ้นเป็นรุ่นปัจจุบันอัตโนมัติ โดยเก็บไฟล์ต้นฉบับไว้
- **ฟิลด์ที่ไม่รู้จัก:** ถ้า `schemaVersion` เท่ากับที่โปรแกรมรู้จักแต่มีฟิลด์ที่ไม่รู้จัก ให้ปฏิเสธ (strict) เพื่อกันการแอบใส่ข้อมูลเข้ามา
  - ยกเว้น `"$schema"` ที่ระดับบนสุด (ต้องเป็น string) ซึ่งรับไว้แล้วไม่สนใจ และไม่เขียนกลับตอนบันทึก เพราะ editor มักใส่ไว้เพื่อตรวจไฟล์กับ schema (phase 1a)
  - ชื่อฟิลด์ซ้ำในออบเจกต์เดียวกันให้ปฏิเสธ และฟิลด์ที่เป็นออบเจกต์ต้องเป็นออบเจกต์จริง ไม่รับ array แทน (phase 1a)
  - ข้อความ error ต้องบอก path ของฟิลด์ (เช่น `colors.ansi[3]`) ผ่านตัวกรองตาม §3.7 และยาวไม่เกิน 300 ตัวอักษร เพราะชื่อฟิลด์มาจากไฟล์ของคนอื่น
- **`id`:** UUID v4 ถ้าตอนนำเข้า id ไปซ้ำกับธีมที่มีอยู่ ให้สร้าง id ใหม่
  - เขียนแบบ 8-4-4-4-12 เป็นเลขฐานสิบหกคั่นด้วยขีด ไม่มีวงเล็บปีกกาหรือ `urn:uuid:` หลักแรกของกลุ่มที่ 3 เป็น `4` และหลักแรกของกลุ่มที่ 4 เป็น `8`, `9`, `a` หรือ `b` (variant ตาม RFC 4122) schema ระบุเป็น pattern ไว้ตรงกัน (phase 1a)
- **`name`:** 1–64 ตัวอักษร · **`author`:** 0–64 ตัวอักษร
- **`tone`:** `"dark"` หรือ `"light"`
- **`simple`:** เป็น `null` หรือ `{accent, tint}` โดย `tint` อยู่ในช่วง 0–0.30
  - มีค่าเมื่อธีมถูกสร้างหรือแก้ล่าสุดในโหมดง่าย
  - กลายเป็น `null` ทันทีที่แก้สีใดๆ ในโหมดละเอียด
- **สีทุกค่า:** ต้องตรงรูปแบบ `^#[0-9a-fA-F]{6}$`
  - `ansi` ต้องมีครบ 16 ค่า เรียงตามมาตรฐาน คือ black, red, green, yellow, blue, magenta, cyan, white แล้วตามด้วยรุ่น bright อีก 8 ค่าในลำดับเดียวกัน
- **`terminal`:**
  - `font` คือชื่อ family ของฟอนต์ ถ้าตอนใช้ธีมเครื่องไม่มีฟอนต์นี้ ให้ใช้ฟอนต์สำรองแทนแล้วแจ้งผู้ใช้
    - ฟอนต์สำรองคือ CaskaydiaCove NF ที่แนบมากับตัวติดตั้ง (founder เลือก 2026-10-11) และโปรแกรมติดตั้งให้ตาม G12 ถ้ายังไม่มี
    - เหตุผล: Windows 10 ไม่มี Cascadia Mono ในระบบ (G12) และการแนบ CaskaydiaCove NF ตัวเดียวไม่ต้องเพิ่มขนาดตัวติดตั้ง
  - `fontSize` 8–32
  - `cursorShape` เป็นได้แค่ `filledBox`, `bar` หรือ `underscore` ซึ่งตรงกับตัวเลือก บล็อก / ขีดตั้ง / ขีดล่าง ในหน้าจอ (G6)
  - `opacity` 30–100
  - `padding` คือ [แนวนอน, แนวตั้ง] ค่าละ 0–40
- **`prompt`:**
  - `layout` เป็น `box`, `line` หรือ `powerline` (เป็น enum ที่จะขยายเพิ่มได้ในรุ่นถัดไป)
  - `segments` คือรายการจาก whitelist ใน §3.5 ห้ามซ้ำ และลำดับในรายการคือลำดับที่แสดง
  - `transient` เป็น bool
- **`banner`:**
  - `title` ยาวไม่เกิน 80 ตัวอักษร
  - `lines` ไม่เกิน 4 บรรทัด บรรทัดละไม่เกิน 80 ตัวอักษร
  - ตัวแปรที่รู้จักคือ `{user}`, `{host}`, `{cwd}`, `{date}`, `{time}` ตัวแปรอื่นแสดงเป็นตัวอักษรตามเดิม
- **JSON Schema:** ฉบับเต็มอยู่ที่ `schema/cmdtheme-1.schema.json` และต้องสร้างจาก type ใน Rust ไม่เขียนด้วยมือ

| ansi 0 / 8 / 7 / 15 | มืด 0.30 / 0.50 / 0.85 / 0.97 · สว่าง 0.25 / 0.45 / 0.85 / 0.98 | 0.01 | hue ของสีหลัก |

- สีที่ออกนอกขอบเขต sRGB ให้ลด C ลงจนอยู่ในขอบเขต
- สร้างเสร็จแล้วให้บังคับเกณฑ์ความอ่านง่ายด้านล่าง โดยขยับแค่ค่า L ห้ามเปลี่ยน h

**โหมดละเอียด**
- แก้สีได้ทั้ง 23 สี (7 สีพื้นฐาน + 16 สี ansi)
- แก้สีไหนก็ตามแล้ว `simple` จะกลายเป็น `null`
- ถ้ากลับไปโหมดง่าย สีที่แก้ไว้ยังอยู่จนกว่าจะเปลี่ยนโทน สีหลัก หรือค่าย้อมพื้นหลัง และหน้าจอต้องมีข้อความบอกเรื่องนี้

**ตัวตรวจความอ่านง่าย**
- คำนวณ contrast ratio ตามสูตรของ WCAG 2.x เทียบกับ background
- เกณฑ์: foreground ต้องได้อย่างน้อย 4.5:1 ส่วน muted, accent, ansi 1–6 และ ansi 9–14 ต้องได้อย่างน้อย 3:1
- ถ้าไม่ผ่าน แค่เตือน ไม่บังคับ
- ปุ่ม "แก้ให้อัตโนมัติ" ขยับค่า L (ใน OKLCH) ของสีที่ไม่ผ่านจนผ่านเกณฑ์

**ฟอนต์และเคอร์เซอร์**
- เลือกฟอนต์ได้จากฟอนต์ความกว้างเท่ากัน (monospace) ที่ติดตั้งในเครื่อง รวมถึง Nerd Font ที่มากับตัวติดตั้ง
- ถ้าเลือก layout แบบ `powerline` โปรแกรมจะสลับไปใช้ Nerd Font ให้เองแล้วแจ้งผู้ใช้

**การบันทึก**
- บันทึกร่างอัตโนมัติลงใน `drafts\` (หน่วงเวลา 1 วินาทีหลังแก้)
- ในหน้าแก้ กด Ctrl+Z / Ctrl+Y เพื่อย้อนหรือทำซ้ำได้ ย้อนได้สูงสุด 100 ขั้น
- เครื่องจะเปลี่ยนก็ต่อเมื่อกด "บันทึกและใช้" เท่านั้น

### 3.5 Prompt

แต่ละ segment ในไฟล์ `.cmdtheme` แปลงเป็น segment ของ OMP ดังนี้:

| segment ใน `.cmdtheme` | segment ของ OMP | หมายเหตุ |
|---|---|---|
| `path` | `path` (`style: "full"`, `home_icon: "~"`) | ✅ ต้นแบบ |
| `git` | `git`: ปิด icon ที่เป็น Nerd Font ทุกตัวเมื่อ layout ไม่ใช่ powerline, แสดงชื่อ branch ตามด้วย `*` เมื่อมีไฟล์แก้ หรือ `✓` เมื่อไม่มี | ✅ ต้นแบบ |
| `time` | `time` (`time_format: "15:04"`) | ✅ ต้นแบบ |
| `user`, `host` | `session` | ⬜ |
| `status` | `status` แสดงเมื่อ exit code ไม่ใช่ 0 | ⬜ |
| `duration` | `executiontime` แสดงเมื่อคำสั่งใช้เวลาเกิน 2 วินาที | ⬜ |

- ห้ามสร้าง segment ชนิดอื่นของ OMP โดยเด็ดขาด โดยเฉพาะ `command` ซึ่งรันคำสั่ง shell ได้
- segment ชนิด `text` ใช้ได้เฉพาะกับตัวอักษรกรอบที่โปรแกรมกำหนดเอง ห้ามรับข้อความจากไฟล์ธีม

Layout แต่ละแบบ:
- **`box`:**
  - บรรทัด 1: `╭─ <segment ฝั่งซ้าย> ─(เส้นเติม)─ <time> ─╮`
  - บรรทัด 2: `│ >` และมี rprompt เป็น `│`
  - ✅ ต้นแบบ
- **`line`:** บรรทัดเดียว `<path> <git> ❯ ` ⬜
- **`powerline`:** แต่ละ segment มีพื้นสีของตัวเอง ต่อกันด้วยลูกศร ต้องใช้ Nerd Font ⬜
- ใน layout `line` และ `powerline` ให้ `time` อยู่ต่อท้ายฝั่งซ้าย
- `transient: true` ทำให้คำสั่งเก่าย่อเหลือ `> ` สีหลัก และต้องตั้ง Clink ให้ `prompt.transient = always` ✅ ต้นแบบ

### 3.6 กล่องต้อนรับ
- **การทำงาน:** สร้างเป็นไฟล์ `banner.lua` จากข้อมูลในธีม แล้วพิมพ์ใน `clink.oninject` ครั้งเดียวต่อเซสชัน กันพิมพ์ซ้ำด้วยตัวแปร environment `CMDSTUDIO_BANNER` ✅ (ต้นแบบใช้ชื่อ `CLAUDE_CMD_BANNER` ห้ามคัดลอกชื่อนี้มาใช้)
- **ภาษา:** สิ่งที่ CMD Studio เขียนในกล่องเอง (วันที่และบรรทัด tips) เป็นภาษาอังกฤษบน Windows ทุกภาษา ภาษาไทยมีเฉพาะในหน้าโปรแกรมของแอป ส่วนข้อความของธีมและค่าของตัวแปร (ชื่อผู้ใช้ ชื่อเครื่อง โฟลเดอร์) แสดงตามที่เป็น (ภาคผนวก B 2026-10-13)
- **หน้าตา:**
  - กรอบเป็นสีหลัก และคำนวณความกว้างด้วย `console.cellcount` ✅
  - มีบรรทัด tips เป็นภาษาอังกฤษ และปิดท้ายด้วยบรรทัดที่มีช่องว่าง 1 ตัว ✅
  - ไอคอนของกล่อง (ต้นแบบใช้ ✻ U+273B) ต้องมีตัวสำรองเมื่อฟอนต์ไม่มีอักษรนั้น ✅ ที่เห็นจริงคือ conhost บน Windows 10 ที่ใช้ฟอนต์เริ่มต้นจะวาดเป็นกล่องว่าง ส่วนใน WT ที่ใช้ CaskaydiaCove NF วาดได้
- **ตัวแปรวันเวลา:**
  - `{date}` เป็นภาษาอังกฤษและปี ค.ศ. เสมอ ไม่ว่า Windows จะเป็นภาษาอะไร: `Fri 09 Oct 2026` ⬜
  - ตัวสร้าง `banner.lua` ต้องฝังตารางชื่อวันและเดือนภาษาอังกฤษเอง ห้ามใช้ `os.date` ของ Lua จัดรูปแบบ ✅ เพราะบน Windows ภาษาไทยได้ `อา. 11 ต.ค. 2026` คือชื่อเป็นไทยตามภาษาของเครื่อง (เจอบน VM ภาษาไทย)
  - `{time}` เป็นรูปแบบ `HH:mm`
- **`clearLogo: true`:** ถ้าบรรทัดที่ 1 และ 2 ของจอเป็นหัวข้อความของ cmd คือขึ้นต้นด้วย `Microsoft Windows [` และ `(c) Microsoft Corporation` ให้ล้างจอก่อนพิมพ์กล่อง ✅ (G4) ทดสอบบน VM Windows 10, 11 และ 11 ภาษาไทยแล้ว หัวข้อความเป็นภาษาอังกฤษทุกเครื่อง เพราะชุดภาษาไทยไม่มี `cmd.exe.mui`
- **ความปลอดภัย:** ข้อความที่มาจากธีมต้องผ่านการกรองตาม §3.7 และ escape เป็น string ของ Lua ผ่านฟังก์ชันเดียวที่มี test ครอบ

### 3.7 ความปลอดภัยของไฟล์ธีม
1. ไฟล์ธีมเป็นข้อมูลล้วน ไม่มีส่วนไหนถูกนำไปรันเป็นโค้ด
2. ไม่รับ config ของ Oh My Posh โดยตรง เพราะมี segment `command` ที่รันคำสั่งได้ prompt ต้องสร้างจาก whitelist ใน §3.5 เท่านั้น
3. ข้อความทุกช่อง (name, author, banner และชื่อฟอนต์) ต้องตัดอักขระควบคุม (U+0000–U+001F, U+007F–U+009F) และ escape sequence ทิ้ง ในช่องเดียวห้ามมีการขึ้นบรรทัดใหม่
   - ตัดตัวคั่นบรรทัด U+2028/U+2029 และตัวควบคุมทิศทางข้อความ (U+202A–U+202E, U+2066–U+2069) ด้วย เพื่อกันการปลอมชื่อหรือนามสกุลไฟล์ (phase 1a)
   - name, author และชื่อฟอนต์ตัดช่องว่างหัวท้ายด้วย ส่วนข้อความในกล่องต้อนรับเก็บช่องว่างไว้ตามเดิม
4. ตัวสร้างไฟล์ Lua ต้อง escape ทุก string ผ่านฟังก์ชันเดียว และมี test ครอบกรณี `]]`, `\`, เครื่องหมายคำพูด, อักษรไทย และ emoji
5. ไฟล์ต้องมีขนาดไม่เกิน 64 KB ถ้า JSON ผิดรูปหรือไม่ตรง schema ให้ปฏิเสธพร้อมบอกว่าช่องไหนผิด (`E_THEME_INVALID`)

### 4.4 หลังใช้ธีม
ทุกครั้งที่ใช้ธีม จะมีแถบแจ้ง "ใช้ธีม X แล้ว · เปิด cmd หน้าต่างใหม่เพื่อดูกล่องต้อนรับกับ prompt" พร้อมปุ่ม "ย้อนกลับ" ซึ่งกู้คืนจากจุดย้อนกลับของการใช้ธีมครั้งนั้น หน้าต่าง Windows Terminal ที่เปิดค้างอยู่จะเปลี่ยนสีเองทันที (G8 ✅) ข้อความจึงบอกได้ว่าสีเปลี่ยนแล้ว ส่วน prompt กับกล่องต้อนรับต้องเปิด cmd หน้าต่างใหม่

### 4.5 ภาษาและการเข้าถึง
หน้าหลักห้ามมีศัพท์เทคนิค ให้ใช้คำในตารางนี้แทน:

| ศัพท์เทคนิค | คำที่ผู้ใช้เห็น |
|---|---|
| AutoRun | ให้ cmd ทุกหน้าต่างใช้ธีมนี้ |
| snapshot / backup | จุดย้อนกลับ |
| Oh My Posh, Clink | ส่วนเสริม (อยู่ในหน้าขั้นสูง) |
| transient prompt | ย่อคำสั่งที่พิมพ์ไปแล้ว |
| WCAG contrast | อ่านง่าย / อ่านยาก |

- ปุ่มขึ้นต้นด้วยคำกริยา
- อะไรที่จะเปลี่ยนเครื่อง ต้องบอกผู้ใช้ก่อนเสมอ และต้องย้อนกลับได้
- ใช้คีย์บอร์ดได้ทุกจุด และ screen reader อ่าน label ได้ทั้งภาษาไทยและอังกฤษ
- ขนาดตัวอักษรเป็นไปตามที่ตั้งไว้ใน Windows และหน้าตาโปรแกรมเป็นโหมดมืดหรือสว่างตาม Windows

### 5.4 ตัวเชื่อมระบบ

**Windows Terminal (`WtSettings`)**
- **ไฟล์ที่ต้องหา:** หา `settings.json` ของ WT ทุกรุ่นที่ติดตั้งอยู่
  - รุ่นจาก Store: `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_8wekyb3d8bbwe\LocalState\settings.json` ✅
  - รุ่น Preview: `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminalPreview_8wekyb3d8bbwe\LocalState\settings.json` ⬜
  - รุ่นที่ไม่ได้แพ็ก: `%LOCALAPPDATA%\Microsoft\Windows Terminal\settings.json` ⬜
- **สิ่งที่แก้:**
  - scheme ชื่อ `CMD Studio` (สร้างครั้งแรก แล้วอัปเดตตัวเดิมในครั้งต่อไป)
  - คีย์ของโปรไฟล์ cmd (guid `{0caa0dad-35be-5f56-a8ff-afceeeaa6101}` ✅) ตาม G6
  - `defaultProfile` เฉพาะเมื่อผู้ใช้เลือก
- **ค่า `commandline` ของโปรไฟล์:**
  - โหมด "cmd ทุกหน้าต่าง": ตั้งเป็น `%SystemRoot%\System32\cmd.exe` เปล่าๆ เสมอ ตามบทเรียนข้อ 2
  - โหมด "เฉพาะใน Windows Terminal": ตั้งเป็น `%SystemRoot%\System32\cmd.exe /k ""<clink-launch>" inject --quiet --profile "<data>\clink-profile""` (G19 ใช้กับโหมดนี้ด้วย) เครื่องหมายคำพูดคู่นอกสุดมีไว้ให้ `cmd /k` ตัดทิ้ง เพราะ cmd ตัดคู่นอกสุดออกเมื่อคำสั่งขึ้นต้นด้วยเครื่องหมายคำพูด และไม่เขียน AutoRun แบบนี้ตั้งใจให้หน้าต่างที่เปิดจากนอก WT ไม่ได้ธีม เป็นรูปแบบเดียวกับต้นแบบรุ่นแรกที่ใช้งานได้ ✅
- **รักษาไฟล์เดิม:** ต้องรักษาคอมเมนต์และรูปแบบไฟล์ไว้ ใช้ `jsonc-parser` 0.34.0 ที่เปิดฟีเจอร์ `cst` ✅ (G9) และเขียนตัวแปลง `serde_json::Value` เป็น `CstInputValue` เอง ถ้าไฟล์ parse ไม่ได้ ห้ามแตะไฟล์ ให้แจ้ง `E_WT_PARSE` พร้อมปุ่มกู้จากจุดย้อนกลับล่าสุด (ถ้ามี)
  - ไฟล์ที่ WT อ่านได้ แต่เขียนคีย์ที่ CMD Studio ดูแลซ้ำ 2 ครั้ง (เช่น `defaultProfile` หรือคีย์ในโปรไฟล์ cmd) หรือซ้อน object และ list ลึกเกิน 64 ชั้น ก็ห้ามแตะเช่นกัน ให้แจ้ง `E_WT_PARSE` พร้อมบอกว่าคีย์ไหนซ้ำ แล้วให้ผู้ใช้แก้ `settings.json` ด้วยมือ เหตุผลคือไม่รู้ว่า WT ใช้ค่าไหนในคีย์ที่ซ้ำ และไฟล์ที่ซ้อนลึกมากทำให้ตัว parse ใช้สแต็กจนล้นได้ (phase 1b)
- **จุดย้อนกลับ:** เก็บค่าเดิมของทุกคีย์ที่แตะ ถ้าคีย์ไหนไม่เคยมีมาก่อน ให้บันทึกว่า "ไม่มี" ตอนย้อนกลับจะได้ลบคีย์นั้นออก
- **ทางที่ไม่เลือก:** ใช้ JSON fragment ของ WT ซึ่งไม่ต้องแตะไฟล์ของผู้ใช้เลย แต่ถ้าผู้ใช้เคยตั้งค่าเองในไฟล์หลัก ค่าของผู้ใช้จะชนะ ข้อนี้เป็นเหตุผลที่ไม่เลือก แต่ยังไม่ได้ยืนยันกับของจริง ⬜

**AutoRun**
- **ตำแหน่ง:** `HKCU\Software\Microsoft\Command Processor\AutoRun` ต้องคงชนิดของค่าเดิมไว้ (REG_SZ หรือ REG_EXPAND_SZ) เปิด key เดิมแล้วแก้แค่ค่านี้ ห้ามสร้าง key ใหม่ทับ (บทเรียนข้อ 9)
- **ส่วนของเรา:** `(if exist "<clink-launch>" "<clink-launch>" inject --autorun --quiet --profile "<data>\clink-profile")` อยู่หน้าสุดของค่าเสมอ (G13 ✅ สำหรับแบบไม่มีวงเล็บ: ทำให้ `cmd /c` ช้าลงราว 14 ms บน CI · แบบมีวงเล็บ ✅ inject ได้จริงในหน้าต่าง cmd บน VM-A, VM-B และ VM-C ใน phase 1b และบน VM-A คำสั่ง `if` ของโปรแกรมอื่นที่ตามหลังยังรันอยู่)
  - ต้องมีวงเล็บ เพราะ `if` และ `for` ของ cmd กินคำสั่งที่เหลือทั้งบรรทัดเป็นของตัวเอง ถ้าไม่มีวงเล็บ คำสั่งของโปรแกรมอื่นที่ต่อหลังเราจะรันเฉพาะตอนที่มีไฟล์ของเรา และถ้าเราต่อหลัง `if` ของคนอื่น ธีมจะโหลดเฉพาะตอนที่เงื่อนไขของเขาเป็นจริง (เจอในรีวิว phase 1a: `if exist "C:\nope\x.bat" "C:\nope\x.bat" & echo B` ไม่พิมพ์อะไรเลย)
  - ต้องอยู่หน้าสุด เพราะวงเล็บกันได้แค่คำสั่งที่ตามหลัง ถ้าอยู่หลัง `if` ของคนอื่นก็ยังถูกกินอยู่ดี
- **path ที่ใช้เรียก Clink (`<clink-launch>`, G19, founder เลือก 2026-10-11):** เลือกตามลำดับนี้ทุกครั้งที่ใช้ธีมหรืออัปเดต runtime แล้วบันทึกไว้ใน `state.json`
  - `detect` อ่านข้อมูลจากเครื่อง ส่วนการเลือกตามลำดับเป็นฟังก์ชัน pure `plan::clink_launch` ใน core จึงทดสอบได้โดยไม่ต้องใช้เครื่องจริง
  1. path จริง `<data>\runtime\clink-<ver>\clink_x64.exe` ถ้ามีแต่อักษร ASCII
  2. ถ้าไม่ใช่ ให้ใช้ path แบบ 8.3 ของโฟลเดอร์ข้อมูล `<data>` (`GetShortPathNameW`) ต่อด้วย `runtime\clink-<ver>\clink_x64.exe` ถ้าผลเป็น ASCII ล้วน
     - ต้องใช้ของโฟลเดอร์ข้อมูล ไม่ใช่ของไฟล์ exe เพราะ `GetShortPathNameW` ใช้ได้กับของที่มีอยู่แล้วเท่านั้น และตอนวางแผนครั้งแรก runtime ยังไม่ได้ติดตั้ง
     - ✅ ลองแล้ว: path แบบ 8.3 ทั้งเส้นใช้ได้บน VM ภาษาไทยและภาษาอังกฤษ ส่วนแบบผสม (`C:\Users\3607~1\AppData\Local\AIRESI~1.CMD\runtime\clink-1.9.34\clink_x64.exe`) ลองบน VM ภาษาไทยเมื่อ 2026-10-11 แล้ว inject ได้
  3. ถ้าข้อ 2 ไม่ได้ path ที่เป็น ASCII (เช่น volume ปิดชื่อแบบ 8.3) ให้ติดตั้ง runtime ของ Clink ไว้ที่ `%ProgramData%\ai.resincore.cmdstudio-<SID ของผู้ใช้>\clink-<ver>\` (ไม่ติดตั้งใต้ `<data>` อีกชุด) แล้วใช้ path นั้น ✅ (ลองแล้วว่า Clink จาก `C:\ProgramData` inject ได้) SID เป็น ASCII และแยกโฟลเดอร์ต่อผู้ใช้จึงไม่ชนกัน
     - โฟลเดอร์ของแต่ละคนต้องอยู่ใต้ `%ProgramData%` โดยตรง ห้ามมีโฟลเดอร์แม่ร่วมกัน (architect แก้เมื่อ 2026-10-11 จากเดิม `%ProgramData%\CMD Studio\<SID>`)
       - เหตุผล: ผู้ใช้ทุกคนสร้างไฟล์และโฟลเดอร์ได้ทั้งใน `%ProgramData%` และในโฟลเดอร์ย่อยที่สืบทอดสิทธิ์ (`BUILTIN\Users:(CI)(WD,AD,WEA,WA)` ✅ จาก `icacls C:\ProgramData` บน Windows 11) และคนที่สร้างโฟลเดอร์จะเป็นเจ้าของ ซึ่งแก้สิทธิ์ของโฟลเดอร์นั้นได้เสมอ
       - ถ้ามีโฟลเดอร์แม่ร่วม คนที่สร้างก่อนจะลบหรือเปลี่ยน Clink ของผู้ใช้คนอื่นได้ แล้ว cmd ทุกหน้าต่างของผู้ใช้คนนั้น รวมถึงหน้าต่างที่เปิดแบบ admin จะรันโปรแกรมที่ถูกเปลี่ยน
     - สร้างโฟลเดอร์พร้อมสิทธิ์ในคำสั่งเดียว (`CreateDirectoryW` ที่ส่ง security descriptor ไปด้วย): ผู้ใช้คนนั้น, SYSTEM และ Administrators ได้ full control และไม่สืบทอดสิทธิ์จาก `%ProgramData%` ⬜ phase 1b
       - ถ้าตอนติดตั้ง `CreateDirectoryW` บอกว่าโฟลเดอร์มีอยู่แล้ว (มีคนสร้างหลังจาก `detect` ตรวจ) ต้องตรวจเจ้าของและสิทธิ์ตามข้อถัดไปอีกรอบก่อนเขียนไฟล์ ถ้าไม่ผ่านให้หยุดด้วย `E_CLINK_PATH`
     - ถ้าโฟลเดอร์มีอยู่แล้ว `detect` ส่งให้ planner ใช้เฉพาะเมื่อเจ้าของเป็นผู้ใช้คนนั้น (หรือ SYSTEM หรือ Administrators) และไม่มีใครนอกจาก 3 กลุ่มนี้เขียนได้ ถ้าไม่ผ่านให้ถือว่าใช้ไม่ได้ เพราะผู้ใช้ทั่วไปลบโฟลเดอร์ของคนอื่นไม่ได้ ⬜ phase 1b
  - ถ้าทั้ง 3 ข้อไม่ได้ path ที่เป็น ASCII หรือ path ของ Clink หรือของ profile มี `%`, `"` หรือ `;` (เพราะ `clink.path` คั่นหลาย path ด้วย `;`) หรือไม่ใช่ Unicode ที่ถูกต้อง ให้หยุดตั้งแต่ขั้นวางแผนด้วย `E_CLINK_PATH` โดยไม่แตะเครื่อง ห้ามเขียน AutoRun หรือ `commandline` ที่ทำให้ cmd ขึ้น error (ใช้กับทั้ง 2 โหมด)
  - profile ยังอยู่ที่ `<data>\clink-profile` แม้ path มีอักษรไทย ✅
  - ถ้าทางที่เลือกยังพังบนเครื่องไหน D3 จะจับได้
- **ถ้ามีค่าของโปรแกรมอื่นอยู่แล้ว:** ใส่ส่วนของเราไว้หน้าสุดแล้วตามด้วย ` & ` และค่าเดิม ห้ามแก้ส่วนของคนอื่น และจุดย้อนกลับต้องเก็บค่าเดิมทั้งสตริง (phase 1a: เดิมเขียนว่าต่อท้าย เปลี่ยนเพราะเรื่อง `if`/`for` ข้างบน)
  - แก้ค่าเดิมเฉพาะจุด ไม่ประกอบสตริงใหม่ทั้งหมด: แยกคำสั่งตามกติกาของ cmd (`"` เปิดปิดการอ้างอิง, `^` นอกเครื่องหมายคำพูดทำให้ตัวถัดไปเป็นตัวอักษรธรรมดา, ตัวคั่นคือ `&`, `&&` และ `||` แต่ `&` ที่ตามหลัง `>` หรือ `<` เป็นส่วนของการ redirect เช่น `2>&1`) แล้วตัดเฉพาะส่วนของเรากับตัวคั่น 1 ตัว ส่วนอื่นเหมือนเดิมทุก byte และเอาส่วนของเราออกแล้วต้องได้ค่าเดิมกลับมาทุก byte (phase 1a)
  - คำสั่งที่มี profile ของเราต้องมีรูปแบบตรงกับส่วนของเราเท่านั้น (แบบมีวงเล็บ หรือแบบ `if exist` ไม่มีวงเล็บ) ถ้าไม่ตรง หรือส่วนของเรา หรือ Clink ตัวอื่นที่ผู้ใช้ตกลงให้ปิด ผูกกับคำสั่งอื่นด้วย `|`, วงเล็บ หรือเครื่องหมายคำพูด ให้หยุดด้วย `E_AUTORUN_WRITE` และบอกให้แก้ด้วยมือ ห้ามลบข้อความของคนอื่นไปด้วย (phase 1a)
  - ถ้าค่าเดิมเป็นคำสั่งที่ cmd เองก็รันไม่ได้อยู่แล้ว (มีคำสั่งว่างระหว่างตัวคั่น, จบด้วย `&&` หรือ `||`, วงเล็บไม่ครบคู่ หรือ `|` ไม่มีคำสั่งตามหลัง) ให้หยุดด้วย `E_AUTORUN_WRITE` แทนการใส่ส่วนของเราที่ไม่มีทางได้รัน (phase 1a) · ค่าที่มีอยู่แต่ไม่ใช่ข้อความธรรมดา (ไม่ใช่ REG_SZ หรือ REG_EXPAND_SZ, จำนวน byte เป็นเลขคี่, UTF-16 ไม่ถูกต้อง หรือมีข้อความอื่นนอกจาก NUL ต่อหลัง NUL ตัวแรก) จะไม่ถูกแก้และไม่ถูกถือว่าไม่มีค่า แต่จะหยุดด้วย `E_AUTORUN_WRITE` และบอกให้แก้ด้วยมือ ทั้งตอนใช้ธีมแบบ "cmd ทุกหน้าต่าง" ตอนย้อนทุกอย่าง และตอน `--cleanup` (phase 1b)
  - ถ้าเจอ Clink ตัวอื่น คำถามต้องแสดงทุกคำสั่งที่จะถูกเอาออก
  - หาส่วนของเราจาก path ของ profile โดยไม่สนตัวพิมพ์เล็กใหญ่ เพราะ path บน Windows ไม่แยกตัวพิมพ์
- **ถ้าเจอ Clink ตัวอื่นใน AutoRun ของ HKCU:** ถามผู้ใช้ว่าจะ
  - "ใช้ของ CMD Studio แทน" โดยเอาส่วนของ Clink เดิมออกจาก AutoRun และเก็บไว้ในจุดย้อนกลับ หรือ
  - ยกเลิก
- **ถ้าเจอ Clink ใน AutoRun ของ HKLM (ติดตั้งให้ทั้งเครื่อง):**
  - แก้ไม่ได้เพราะต้องใช้สิทธิ์ admin
  - ให้แจ้งผู้ใช้ตรงๆ ว่า prompt ของ CMD Studio อาจไม่ทำงาน เพราะ Clink ตัวนั้นถูกโหลดก่อนเสมอ ส่วนสีใน WT ยังใช้ได้
  - เป็นข้อจำกัดที่รู้แล้วของ v1 และพฤติกรรมจริงยังต้องยืนยัน ⬜

**Clink**
- `clink-profile\clink_settings` ตั้งค่าดังนี้: `clink.logo = none`, `prompt.transient = always` หรือ `off` ตามธีม, `clink.path = <data>\generated` และ `clink.autoupdate = off` ✅ (G16)
- `generated\init.lua` โหลด OMP โดยใช้ path เต็มของ `runtime\omp-<ver>\oh-my-posh.exe` ไม่พึ่ง PATH ✅ (G17) ใช้รูปแบบ `'""' .. exe .. '" init cmd --config "' .. config .. '" 2>nul"'` และฝัง path ตอนสร้างไฟล์ผ่านฟังก์ชัน escape ตัวเดียวตาม §3.7
  - ` 2>nul` (phase 1a) กันไม่ให้ข้อความ error ของ cmd หรือ OMP โผล่ในทุกหน้าต่างเมื่อไฟล์ OMP หาย เพราะ `io.popen` อ่านแค่ stdout ส่วนปัญหานั้น D2 รายงานแทน ✅ ลองบน VM-A ใน phase 1b: เมื่อไม่มีไฟล์ OMP หน้าต่าง cmd ไม่มีข้อความ error และ D2 รายงาน
  - สคริปต์ที่ OMP สร้างรันใต้ `pcall` ถ้าพังให้บันทึกลง log ไม่พิมพ์ error ใส่ทุกหน้าต่าง (phase 1a)

**ฟอนต์ (`Fonts`)**
- ติดตั้งแบบรายผู้ใช้ตาม G12 ✅ และติดตั้งเฉพาะเมื่อธีมต้องใช้ (คือ Nerd Font ที่แนบมา)
- ชื่อตระกูลที่ใช้ทั้งตอนตรวจว่ามีฟอนต์และตอนเขียน `font.face` ของ WT คือ `CaskaydiaCove NF` ✅ WT รับชื่อ `CaskaydiaCove Nerd Font` ได้ด้วย แต่ GDI เห็นแค่ชื่อแรก
- WT ไม่เตือนเลยเมื่อหาฟอนต์ใน `font.face` ไม่เจอ มันจะใช้ Cascadia Mono แทนเงียบๆ ✅ จึงต้องตรวจเองด้วย D8
- Windows 11 มี Cascadia Code และ Cascadia Mono ติดตั้งในระบบแล้ว แต่ Windows 10 ไม่มี ✅ (นับจากรายชื่อฟอนต์ที่ GDI เห็น)
  - conhost ใช้ได้เฉพาะฟอนต์ในระบบ
  - WT แนบ Cascadia มาในแพ็กเกจของตัวเอง จึงอาจวาดได้แม้ระบบไม่มี ⬜ ยังไม่ได้ลอง (ใน VM ที่ลองไม่มี WT บน Windows 10)
  - ตัวสำรองตาม §3.3 คือ CaskaydiaCove NF ที่แนบมา (founder 2026-10-11) · D8 ใน v1 นับเฉพาะฟอนต์ที่ GDI เห็น ไม่นับฟอนต์ในแพ็กเกจของ WT (ตัดสินใน phase 1b) เมื่อ GDI ไม่เห็นฟอนต์ของธีม planner จึงใช้ตัวสำรองเสมอ
- จุดย้อนกลับต้องบันทึกว่าเราเป็นคนติดตั้ง ตอนถอนจะได้ถอนเฉพาะฟอนต์ที่เราติดตั้ง

**ไฟล์ (`Fs`)**
- เขียนแบบ atomic: เขียนไฟล์ชั่วคราวในโฟลเดอร์เดียวกัน → flush → rename แทนที่
- runtime ติดตั้งเป็นโฟลเดอร์ใหม่ตามเวอร์ชัน ห้ามเขียนทับโฟลเดอร์ที่มีอยู่

### 5.5 ทรานแซกชัน "ใช้ธีม"
- **สถานะ:** `planned → snapshotted → applying(i/n) → verifying → committed` หรือถ้าพัง `→ rollingBack → rolledBack` หรือ `rollbackIncomplete` (ชื่อใน `journal.json` เป็น camelCase เหมือน JSON ทุกไฟล์ที่ CMD Studio เขียน, phase 1a)
- **journal:** เขียน `journal.json` ก่อนเปลี่ยนสถานะทุกครั้ง (write-ahead) จึงช้ากว่าเครื่องจริง 1 operation เสมอ: บันทึก `snapshotted` ก่อนเริ่ม operation แรก และบันทึก `applying(i)` หลัง operation ที่ i เสร็จ
- **กู้หลังดับกลางทาง (phase 1a):** ย้อน operation ที่อาจถูกแตะแล้ว จากใหม่ไปเก่า
  - `planned` ไม่ย้อนอะไร เพราะยังไม่ได้ถ่ายจุดย้อนกลับและยังไม่ได้แตะเครื่อง
  - `snapshotted` ย้อน operation แรก เพราะอาจเขียนไปครึ่งเดียว
  - `applying(i)` ย้อน operation ที่ 1 ถึง i+1 · `verifying` ย้อนทุกตัว · `rollingBack(from)` ย้อนต่อจากจำนวนเดิม
  - การย้อนต้องทำซ้ำได้ เพราะอาจถูกเรียกกับของที่ยังไม่ถูกแตะ ของที่เขียนไปครึ่งเดียว หรือย้อนซ้ำหลังดับระหว่างย้อน
- **ทำซ้ำได้:** ทุก operation ต้องทำซ้ำได้โดยไม่เสียหาย (idempotent)
- **ขั้นตรวจผล มี 4 ข้อ:**
  1. อ่านค่าที่เขียนไปกลับมาเทียบ
  2. `oh-my-posh print primary --config <generated>` ต้องสำเร็จ
  3. `clink_x64.exe --profile <p> set clink.logo` ต้องโหลด Lua ได้โดยไม่มี error (G5 ✅): ให้ดูว่า output มีบรรทัดที่เข้ากับ `\.lua:\d+:` หรือไม่ ถ้ามีให้แจ้ง `E_VERIFY_CLINK` ห้ามดูจาก exit code เพราะเป็น 0 เสมอ
  4. parse `settings.json` ของ WT ที่เพิ่งเขียนได้
- **ถ้าโปรแกรมดับกลางทาง:** เปิดขึ้นมาใหม่แล้วเจอ journal ที่ยังไม่จบ ให้ย้อนกลับอัตโนมัติแล้วแจ้งผู้ใช้
  - ย้อนตอนเริ่มทุกคำสั่งที่เปลี่ยนเครื่อง (ใช้ธีม, ย้อนกลับ, ย้อนทุกอย่าง และ `--cleanup`) ส่วน doctor อ่านอย่างเดียว จึงไม่ย้อนเอง แต่แจ้งว่ามีการเปลี่ยนแปลงที่ค้างอยู่ (§5.8) (phase 1b)
  - ถ้าตอนนั้นอ่าน journal ของมันไม่ได้ (เช่น ไฟล์ถูกล็อกหรือกำลังถูกสแกน) ทุกคำสั่งที่เปลี่ยนเครื่องจะหยุดด้วย `E_SNAPSHOT_READ` โดยไม่เปลี่ยนอะไร แล้วให้ลองใหม่ เพราะถ้าทำต่อ จุดย้อนกลับใหม่จะกลายเป็นจุดล่าสุด และการเปลี่ยนแปลงที่ค้างจะไม่ถูกย้อนอีกเลย ถ้าจุดนั้นอ่านไม่ได้ตลอด ทางออกคือคำสั่ง `cmdstudio set-aside <id>` ซึ่งกันจุดนั้นไว้ต่างหาก แต่สิ่งที่มันเปลี่ยนไว้ต้องแก้ด้วยมือ (phase 1b)
  - จุดย้อนกลับที่ไฟล์หายหรือเสีย จะถูกกันไว้ต่างหาก (เปลี่ยนชื่อ journal เป็น `journal.unreadable.json` และเก็บไว้ให้ดู) แล้วแจ้งครั้งเดียว ส่วนจุดที่อ่านไม่ได้แค่ชั่วคราวจะแจ้งทุกครั้งจนกว่าจะอ่านได้ ทั้งสองแบบไม่ขวาง doctor (phase 1b)
- **ถ้าย้อนกลับไม่ครบ (`rollbackIncomplete`):** ต้องแจ้งชัดว่าส่วนไหนคืนไม่ได้ พร้อมวิธีแก้ด้วยมือ ห้ามรายงานว่าสำเร็จ · รายการนี้และวิธีแก้เก็บใน `snapshots\<id>\incomplete.json` ข้าง journal (ไม่เก็บใน `state.json` เพราะ `state.json` เองก็อาจเป็นไฟล์ที่คืนไม่ได้) จึงยังแจ้งได้หลังเปิดโปรแกรมใหม่ จนกว่าจะมีทรานแซกชันใหม่ (phase 1b) · ถ้าบันทึกรายการนี้ไม่สำเร็จ ผลของคำสั่งจะบอกไว้ และตอนเริ่มคำสั่งครั้งถัดไปจะสร้างรายการนี้ใหม่จาก journal ของจุดย้อนกลับนั้นแล้วบันทึกอีกครั้ง ส่วน doctor (R3) และ `--cleanup` อ่านรายการที่สร้างใหม่แบบเดียวกันโดยไม่เขียนอะไร (phase 1b)
  - ระหว่างที่บันทึกนี้ยังค้างอยู่ หรือยังอ่านบันทึกนี้ไม่ได้ ปุ่ม "ย้อนกลับ" จะไม่ทำงาน เพราะการย้อนการใช้ธีมครั้งก่อนหน้าจะทำให้บันทึกของสิ่งที่ต้องแก้หายไป ส่วน "ย้อนทุกอย่าง" ยังทำได้ และย้ายรายการที่ยังคืนไม่ได้ไปไว้ในบันทึกของจุดย้อนกลับของมันเอง จึงยังแจ้งต่อไป (phase 1b) · แต่ถ้าตอนนี้อ่านบันทึกนี้ไม่ได้ (เช่น มีโปรแกรมสแกนเปิดไฟล์ค้างไว้) "ย้อนทุกอย่าง" และ `--cleanup` จะหยุดด้วย `E_SNAPSHOT_READ` ก่อนเปลี่ยนหรือลบอะไร แล้วให้ลองใหม่ เพราะจุดย้อนกลับใหม่ของมันจะทำให้บันทึกนี้ไม่ถูกแจ้งอีก ส่วนบันทึกที่เสียไม่ขวาง (phase 1b)
- **ทำงานทีละคำสั่ง:** ทุกคำสั่งที่เปลี่ยนเครื่อง (ใช้ธีม, ย้อนกลับ, ย้อนทุกอย่าง และ `--cleanup`) ถือล็อก `<data>\cmdstudio.lock` ตลอดคำสั่ง ไม่ว่าจะมาจากแอปหรือ CLI ถ้ามีตัวอื่นถืออยู่ ให้หยุดทันทีด้วย `E_BUSY` โดยไม่รอ ส่วน doctor ไม่ใช้ล็อกนี้ (phase 1b)
- **ลำดับของจุดย้อนกลับ:** id ของจุดย้อนกลับใหม่ต้องไม่ย้อนเวลา แม้นาฬิกาของเครื่องจะถอยหลัง (ถ้านาฬิกาตามหลังจุดล่าสุด ให้ใช้เวลาของจุดล่าสุดบวก 1 ms) เพราะการกู้หลังโปรแกรมดับและ "ย้อนกลับ" ดูจากลำดับนี้ (phase 1b)
- **การเก็บจุดย้อนกลับ:** เก็บ 20 จุดล่าสุด ส่วนจุดแรกสุดซึ่งเป็นค่าเดิมก่อนติดตั้งเก็บไว้ตลอด · จุดที่อาจเป็นสำเนาเดียวของค่าเดิมของผู้ใช้จะไม่ถูกลบ ได้แก่จุดที่ journal ยังไม่จบ อ่านไม่ได้ หรือจบแบบย้อนกลับไม่ครบ จุดที่ถูกกันไว้ต่างหากพร้อม journal และจุดที่มี `incomplete.json` (phase 1b)

### 5.6 พรีวิว

| `cmdstudio doctor [--json]` | ตรวจสุขภาพ |
| `cmdstudio undo` | ย้อนการใช้ธีมครั้งล่าสุด |
| `cmdstudio set-aside <id>` | กันจุดย้อนกลับที่อ่านไม่ได้ไว้ต่างหาก ใช้เมื่อ doctor (R1) บอกให้ใช้ · ไม่ยอมกันจุดที่ยังอ่านได้ · สิ่งที่การเปลี่ยนแปลงของจุดนั้นทำไว้จะไม่ถูกย้อนเอง ต้องตรวจด้วยมือ และถ้าเป็นจุดล่าสุดจะบันทึกไว้ใน `incomplete.json` ให้แจ้งต่อ (§5.5) |

exit code: `0` สำเร็จ · `1` ล้มเหลวและย้อนกลับแล้ว · `2` input ไม่ถูกต้อง · `3` ย้อนกลับไม่ครบ

ทุกคำสั่งรับ `--data-dir <dir>` และ `--resources <dir>` แทนโฟลเดอร์ข้อมูลและโฟลเดอร์ `resources\` ข้าง exe (ใช้ในเทสต์) ทั้งสองต้องเป็น path เต็ม · ก่อนทำคำสั่งที่เปลี่ยนเครื่อง (`apply`, `undo`, `--cleanup`, `set-aside`) CLI จะย้อนทรานแซกชันที่ค้างจากครั้งก่อนให้เสร็จก่อน (§5.5) ถ้าย้อนไม่ครบ `apply` และ `undo` จะหยุดด้วย exit code `3` ส่วน `--cleanup` และ `set-aside` ทำต่อเพราะเป็นทางแก้ · `doctor` และ `--help` อ่านอย่างเดียว ไม่ถือล็อกและไม่ย้อนอะไร (§5.8) · ถ้าการย้อนกลับครั้งล่าสุดไม่ครบ (มี `incomplete.json`) CLI จะแจ้งรายการที่ต้องแก้ด้วยมือก่อนทุกคำสั่งที่เปลี่ยนเครื่อง จนกว่าจะมีทรานแซกชันใหม่ (doctor แจ้งใน R3) · `apply` ที่เจอ Clink ตัวอื่นจะแสดงทุกคำสั่งที่จะถูกเอาออกแล้วจบด้วย `2` ส่วนค่า AutoRun ที่แก้อย่างปลอดภัยไม่ได้ (`E_AUTORUN_WRITE`) จะแสดงคำสั่งนั้นพร้อมวิธีแก้ด้วยมือแล้วจบด้วย `1` · คำสั่งที่ถูกปฏิเสธก่อนเปลี่ยนการตั้งค่าของผู้ใช้ (ไฟล์ฟอนต์ที่ CMD Studio ค้างไว้ให้ลบอาจถูกลบไปก่อนแล้ว CLI จึงบอกว่า "ยังไม่ได้เปลี่ยนการตั้งค่าของคุณ" ไม่ใช่ "ยังไม่ได้เปลี่ยนอะไร") (`E_BUSY`, `E_SNAPSHOT_READ` ระหว่างที่ยังตรวจการเปลี่ยนแปลงที่ค้างไม่ได้ และ `undo` ระหว่างที่บันทึกการย้อนกลับที่ไม่ครบยังค้าง) จบด้วย `1` · `--cleanup` แจ้งทุกขั้นที่ไม่สำเร็จพร้อมรหัสทาง stderr และจบด้วย `3` เมื่อทำไม่ครบ ซึ่งรันซ้ำแล้วอาจจบได้ · `--cleanup --data-dir` ลบทุกอย่างในโฟลเดอร์ยกเว้น `themes\` จึงทำต่อเฉพาะเมื่อโฟลเดอร์ไม่มีอยู่ ว่าง หรือทุกอย่างในโฟลเดอร์เป็นสิ่งที่ CMD Studio ใส่ไว้เอง และเป็นชนิดที่ถูก (โฟลเดอร์ `generated\`, `clink-profile\`, `runtime\`, `snapshots\`, `themes\` และไฟล์ `state.json`, `cmdstudio.lock`, `state.json.damaged-<ms>` และไฟล์ชั่วคราว `.state.json.<hex 32 ตัว>.cmdstudio-tmp` ที่การเขียนซึ่งถูกตัดกลางทางทิ้งไว้ เทียบชื่อโดยไม่สนตัวพิมพ์เล็กใหญ่) และถ้ามีมากกว่า `themes\` ต้องมีไฟล์ของ CMD Studio เองอย่างน้อยหนึ่งไฟล์ (`cmdstudio.lock`, `state.json` หรือ `state.json.damaged-<ms>`) เพราะโฟลเดอร์ที่มีแต่โฟลเดอร์ชื่อเหมือนของ CMD Studio อาจเป็นของคนอื่น (phase 1b) ยกเว้นโฟลเดอร์ที่มีแต่ `themes\` เมื่อใส่ `--remove-themes` เพราะอาจเป็นของคนอื่น นอกนั้นจะไม่สร้างหรือลบอะไร บอกชื่อสิ่งที่ไม่ใช่ของ CMD Studio ให้ย้ายออก หรือบอกชื่อไฟล์ของ CMD Studio ที่ไม่มี แล้วให้ตรวจ path และจบด้วย `2` · `doctor` จบด้วย `1` เมื่อมีข้อที่ล้มเหลว รวมทั้ง R1–R3 · CLI พูดภาษาอังกฤษอย่างเดียว ไม่ว่า Windows จะเป็นภาษาอะไร และไม่มีตัวเลือก `--lang` (ใส่มาจะเป็น input ไม่ถูกต้อง จบด้วย `2`) ข้อความที่ core มีทั้งสองภาษา CLI แสดงภาษาอังกฤษ ส่วนภาษาไทยเก็บไว้ให้หน้าโปรแกรมของแอป `doctor --json` จึงมี `messageEn` แต่ไม่มี `messageTh` · ชื่อ path และคำที่ผู้ใช้พิมพ์หรือตั้งเองแสดงตามที่เขียน แม้เป็นภาษาไทย

### 5.8 ตรวจสุขภาพ

| รหัส | ตรวจอะไร |
|---|---|
| D1 | ไฟล์ runtime อยู่ครบและ hash ตรง |
| D2 | `oh-my-posh version` รันได้และตรงกับเวอร์ชันที่ pin ไว้ |
| D3 | Clink โหลดสคริปต์ของเราได้ (ตรวจจาก output ของ `clink set` ตาม G5) และ inject ได้จริงจาก path ของ runtime (หลังเปิด cmd ใน `clink.log` ต้องไม่มี `Unable to get DLL version` หรือ `Failed to copy DLL` ตาม G19) · อ่านเฉพาะส่วนของ `clink.log` ที่เขียนหลังใช้ธีม ถ้ายังไม่มีหน้าต่าง cmd ไหน inject ให้เตือน `E_THEME_NOT_LOADED` พร้อมบอกให้เปิดหน้าต่างใหม่ ในโหมด "cmd ทุกหน้าต่าง" ถ้ายังเป็นอยู่ให้แก้ AutoRun ด้วยมือ ส่วนโหมด "เฉพาะใน Windows Terminal" ให้เปิดแท็บ cmd ใหม่ใน WT และถ้ายังเป็นอยู่ให้ใช้ธีมซ้ำ (phase 1a: ตัวอ่าน AutoRun ของ planner ยอมรับค่าบางแบบที่ cmd ไม่รัน มีแต่หน้าต่าง cmd จริงที่บอกได้) |
| D4 | AutoRun มีส่วนของเราที่มี guard อยู่หน้าสุด และชี้ไปที่ runtime ที่มีอยู่จริง (ตรวจเมื่ออยู่ในโหมด "cmd ทุกหน้าต่าง") · ค่าที่ cmd รันไม่ได้ทั้งค่าให้แจ้ง `E_AUTORUN_WRITE` พร้อมวิธีแก้ด้วยมือ · ค่าที่ไม่ใช่ข้อความธรรมดา (§5.4) ห้ามอ่านว่าไม่มีค่าและ CMD Studio ไม่แก้ให้ ให้แจ้ง `E_AUTORUN_WRITE` พร้อมวิธีแก้ด้วยมือใน Registry Editor (phase 1b) |
| D5 | ไม่มี Clink ตัวอื่นใน AutoRun ทั้ง HKCU และ HKLM (ถ้ามีจะเตือน) · ค่าที่ไม่ใช่ข้อความธรรมดา (§5.4) CMD Studio ไม่แก้และห้ามอ่านว่าไม่มี Clink ถ้าค่าอีกตัวไม่มีอะไรให้เตือน ให้แจ้งว่าตรวจไม่ได้ (`skipped`) พร้อมบอกให้แก้ด้วยมือ (phase 1b) |
| D6 | มี WT ติดตั้งอยู่ และ `settings.json` ของทุกรุ่น parse ได้ · WT ที่ติดตั้งแล้วแต่ยังไม่เคยเปิดจะยังไม่มี `settings.json` ให้เตือนว่าเปิด WT หนึ่งครั้งแล้วใช้ธีมซ้ำ (CMD Studio ไม่สร้างไฟล์นี้เอง) |
| D7 | โปรไฟล์ cmd มี `commandline` ตรงตามโหมด, ใช้ `colorScheme` ชื่อ `CMD Studio` และเป็นโปรไฟล์ค่าเริ่มต้นถ้าผู้ใช้เลือกไว้ · `commandline` ต้องตรงกับที่ planner เขียนทุกตัวอักษร · ไฟล์ที่เขียนคีย์ของเราซ้ำหรือซ้อนลึกเกิน 64 ชั้นให้แจ้ง `E_WT_PARSE` พร้อมเหตุผล (§5.4) (phase 1b) |
| D8 | ฟอนต์ที่ธีมต้องใช้ติดตั้งอยู่ ข้อนี้สำคัญเพราะ WT ไม่เตือนเองเมื่อหาฟอนต์ไม่เจอ (G12) · นับเฉพาะฟอนต์ที่ GDI เห็น ไม่นับฟอนต์ในแพ็กเกจของ WT (§5.4) |
| D9 | ไฟล์ใน `generated\` ตรงกับ hash ใน `state.json` ถ้าไม่ตรงแปลว่ามีคนแก้ด้วยมือ ให้เสนอให้ใช้ธีมซ้ำ · ถ้าอ่าน `state.json` ไม่ได้ ให้แจ้ง `E_STATE_INVALID` ที่ข้อนี้ ส่วนข้อที่ต้องรู้ว่าใช้ธีมอะไรอยู่จะข้ามไปพร้อมบอกเหตุผล ห้ามบอกว่า "ยังไม่ได้ใช้ธีม" (phase 1b) |
| D10 | แอปรันแบบไม่ได้แพ็ก (ตรวจไว้กันพลาด) · ถ้า Windows ตอบไม่ได้ว่าแอปไม่ได้อยู่ในแพ็กเกจ ให้ถือว่าอยู่ (phase 1b) |
| D11 | แอปเทอร์มินัลเริ่มต้นของ Windows เป็น WT (แสดงเป็นข้อมูลอย่างเดียว เฉพาะ Windows 11) · ถ้าอ่านรุ่นของ Windows หรือค่าแอปเทอร์มินัลเริ่มต้นไม่ได้ ให้ข้ามพร้อมบอกว่าอ่านอะไรไม่ได้ ห้ามเดา (phase 1b) |

กติกาของ doctor ทุกข้อ (phase 1b):
- doctor อ่านอย่างเดียว ไม่เขียนอะไร ไม่ถือล็อก `cmdstudio.lock` และไม่ย้อนการเปลี่ยนแปลงที่ค้าง จึงไม่ถูกขวางด้วย CMD Studio อีกตัวที่กำลังทำงาน จุดย้อนกลับที่อ่านไม่ได้ หรือ `state.json` ที่อ่านไม่ได้ แต่แจ้งสิ่งเหล่านี้แล้วตรวจข้ออื่นต่อ
- ข้อที่อ่านสิ่งที่ต้องตรวจไม่ได้ (registry, ไฟล์ หรือรายชื่อฟอนต์) ให้แจ้ง `fail` ด้วย `E_MACHINE_READ` พร้อมข้อความ error ห้ามแจ้งว่า `ok` และห้ามแจ้งเป็นปัญหาที่ข้อนั้นตรวจหา เช่น ไฟล์ที่อ่านไม่ได้ ไม่ได้แปลว่าไฟล์หายหรือถูกแก้
- หลัง D1–D11 จะมีบรรทัดเพิ่มเฉพาะเมื่อจุดย้อนกลับมีปัญหา ถ้าไม่มีปัญหาก็ไม่มีบรรทัดเหล่านี้:

| รหัส | แจ้งเมื่อ |
|---|---|
| R1 | มี CMD Studio อีกตัวกำลังเปลี่ยนเครื่องอยู่ (`warn`, `E_BUSY`) · การเปลี่ยนแปลงล่าสุดถูกตัดกลางทางและยังไม่ได้ย้อน ซึ่งจะย้อนตอนเริ่มคำสั่งถัดไปที่เปลี่ยนเครื่อง (`warn`, `E_TXN_INTERRUPTED`) · จุดย้อนกลับของมันเสียหรือไฟล์หาย คำสั่งถัดไปที่เปลี่ยนเครื่องจะกันจุดนั้นไว้ต่างหาก แล้วต้องตรวจด้วยมือ (`warn`, `E_SNAPSHOT_READ`) · หรือตอนนี้อ่านจุดย้อนกลับของมันไม่ได้ จึงยังตรวจไม่ได้ และทุกคำสั่งที่เปลี่ยนเครื่องจะหยุดจนกว่าจะอ่านได้ (`fail`, `E_SNAPSHOT_READ` พร้อมทางออก `cmdstudio set-aside <id>`) |
| R2 | อ่านจุดย้อนกลับอื่นไม่ได้ (`E_SNAPSHOT_READ`) |
| R3 | การย้อนกลับครั้งล่าสุดทำได้ไม่ครบ พร้อมรายการที่ต้องแก้ด้วยมือทั้งภาษาไทยและอังกฤษ (ภาษาอังกฤษอยู่ในรายละเอียดที่ CLI แสดง ภาษาไทยอยู่ใน `details_th` ให้แอป) (`E_ROLLBACK_INCOMPLETE`) หรืออ่านบันทึกนั้นไม่ได้ (`E_SNAPSHOT_READ`) |

### 5.9 รหัสปัญหา
ทุกปัญหาที่ผู้ใช้เห็นต้องมี 3 อย่าง คือ รหัสที่คงที่, ข้อความภาษาคนทั้งไทยและอังกฤษ และรายละเอียดทางเทคนิคที่กดเปิดดูได้ · CLI แสดงรหัสกับข้อความภาษาอังกฤษเท่านั้น ส่วนความหมายภาษาไทยในตารางนี้มีไว้ให้หน้าโปรแกรมของแอป

| รหัส | ความหมาย | English |
|---|---|---|
| `E_WT_NOT_FOUND` | ไม่พบ Windows Terminal หรือพบแต่ยังไม่เคยเปิด จึงยังไม่มี `settings.json` (D6) | Windows Terminal was not found, or was never opened, so it has no settings.json yet (D6) |
| `E_WT_PARSE` | parse `settings.json` ของ WT ไม่ได้ หรือไฟล์เขียนคีย์ที่ CMD Studio ดูแลซ้ำ หรือซ้อนลึกเกิน 64 ชั้น (§5.4) ต้องแก้ไฟล์ด้วยมือ | Windows Terminal's settings.json can't be parsed, writes a key CMD Studio owns twice, or nests deeper than 64 levels (§5.4); fix it by hand |
| `E_WT_WRITE` | เขียน `settings.json` ของ WT ไม่ได้ หรือ (D7) โปรไฟล์ cmd ใน WT ไม่ตรงกับธีม | Windows Terminal's settings.json could not be written, or (D7) its cmd profile does not match the theme |
| `E_AUTORUN_FOREIGN_CLINK` | เจอ Clink ตัวอื่นใน AutoRun | Another Clink runs from AutoRun |
| `E_AUTORUN_WRITE` | เขียน AutoRun ไม่ได้ หรือแก้อย่างปลอดภัยไม่ได้จึงต้องแก้ด้วยมือ หรือ (D4) ส่วนของเราหายไปหรือไม่อยู่หน้าสุด | AutoRun could not be written, or can't be changed safely and needs a hand edit, or (D4) CMD Studio's part is gone or not first |
| `E_CLINK_PATH` | ไม่มี path ที่ cmd ใช้เรียก Clink ได้อย่างปลอดภัย: ไม่มีทางไหนใน `<clink-launch>` ที่เป็น ASCII ล้วน (G19) หรือ path มี `%`, `"` หรือ `;` หรือไม่ใช่ Unicode ที่ถูกต้อง (§5.4) · หรือ (D3) Clink inject จากโฟลเดอร์ของมันไม่ได้ (G19) | No path cmd can use to start Clink safely: no `<clink-launch>` choice is all ASCII (G19), or a path holds `%`, `"` or `;` or is not valid Unicode (§5.4); or (D3) Clink can't inject from its folder (G19) |
| `E_FONT_INSTALL` | ติดตั้งฟอนต์ไม่สำเร็จ หรือ (D8) ไม่พบฟอนต์ของธีม | The font could not be installed, or (D8) the theme's font is not installed |
| `E_RUNTIME_MISSING` | ไฟล์ runtime หาย ถูกแก้ หรือรันไม่ได้ (D1–D4) หรือไฟล์ที่แนบมากับ CMD Studio หายหรือเสีย | Runtime files are missing, changed or do not run (D1–D4), or the files that come with CMD Studio are missing or damaged |
| `E_VERIFY_OMP` | ขั้นตรวจผล: OMP เรนเดอร์ config ไม่ได้ | Verify: Oh My Posh can't render the config |
| `E_VERIFY_CLINK` | ขั้นตรวจผล: Clink โหลดสคริปต์ไม่ได้ (D3 ด้วย) | Verify: Clink can't load the scripts (D3 too) |
| `E_VERIFY_READBACK` | ขั้นตรวจผล: ค่าที่อ่านกลับมาไม่ตรงกับที่เขียน | Verify: a value read back differs from what was written |
| `E_SNAPSHOT_WRITE` | ถ่ายจุดย้อนกลับไม่สำเร็จ | A restore point could not be written |
| `E_THEME_INVALID` | ไฟล์ธีมผิดรูปแบบ | The theme file is not valid |
| `E_THEME_NEWER_SCHEMA` | ไฟล์ธีมมาจากโปรแกรมรุ่นใหม่กว่า | The theme file comes from a newer version |
| `E_ROLLBACK_INCOMPLETE` | ย้อนกลับได้ไม่ครบ | The rollback did not finish; some parts must be fixed by hand |
| `E_TXN_INTERRUPTED` | การเปลี่ยนแปลงครั้งก่อนถูกตัดกลางทาง (โปรแกรมดับ) และย้อนกลับให้ตอนเริ่มคำสั่งถัดไปที่เปลี่ยนเครื่อง · doctor แจ้งเมื่อยังไม่ได้ย้อน (§5.5) | An earlier change was cut off (the app stopped); it is rolled back when the next command that changes the machine starts, and doctor reports one not rolled back yet (§5.5) |

| `E_DATA_WRITE` | เขียนลงโฟลเดอร์ข้อมูลของโปรแกรมไม่ได้ เช่น ไฟล์ใน `generated\` หรือ `state.json` | Could not write to CMD Studio's data folder, such as a file in `generated\` or state.json |

One that could not be opened or is from a newer CMD Studio is never written over; a damaged one is replaced by undo with the state.json from before that apply, and renamed state.json.damaged-<ms> by Revert everything and --cleanup |
| `E_GENERATED_EDITED` | มีคนแก้ไฟล์ใน `generated\` ด้วยมือ (D9) | A file in `generated\` was edited by hand (D9) |

### 5.10 Log ความเป็นส่วนตัว และความปลอดภัยของแอป
- ไม่มี telemetry ใดๆ
- ข้อมูลวินิจฉัยออกจากเครื่องก็ต่อเมื่อผู้ใช้กดคัดลอกเองเท่านั้น
- path ที่มีชื่อผู้ใช้อยู่ จะถูกแทนด้วย `%USERNAME%` ก่อนคัดลอก
- เปิด capability ของ Tauri เฉพาะคำสั่ง IPC ใน §5.7 เท่านั้น
- ตั้ง CSP ห้ามโหลดสคริปต์หรือเนื้อหาจากภายนอก หน้าจอทั้งหมดอยู่ในตัวแอป
- โปรแกรมรันแค่ไฟล์ที่แนบมาเองใน `runtime\` ด้วย argument ที่โปรแกรมกำหนด ห้ามรันคำสั่งที่มาจากไฟล์ธีมหรือ input ของผู้ใช้

## 6. ติดตั้ง อัปเดต ถอน และการปล่อย

### 6.1 ตัวติดตั้ง
- ใช้ NSIS แบบรายผู้ใช้ (`currentUser`) จึงไม่ต้องใช้ admin และติดตั้งที่ `%LOCALAPPDATA%\CMD Studio` ✅ (G10)
- ตัวติดตั้งเป็นไฟล์เดียว ประเมินขนาดไว้ราว 20–30 MB
  - ที่วัดจริงแล้ว: OMP 14.4 MB และ Clink x64 2.9 MB ✅
  - ยังเป็นการประเมิน: ตัวแอปกับฟอนต์ ⬜
- ใช้ค่าเริ่มต้นของ Tauri สำหรับ WebView2 คือ `downloadBootstrapper` ✅ (G10) เพราะ `embedBootstrapper` ช่วยแค่ Windows 7 ซึ่งอยู่นอกขอบเขต
- ติดตั้งได้โดยไม่ต้องใช้เน็ต ยกเว้นเครื่องที่ไม่มี WebView2
- ถ้าเป็นเครื่อง ARM64 ตัวติดตั้งจะแจ้งว่ายังไม่รองรับแล้วหยุด เพราะ Clink x64 inject เข้า cmd ที่เป็น ARM64 ไม่ได้
- ติดตั้งเสร็จแล้วเปิดโปรแกรมให้เอง

### 6.2 อัปเดต
- ใช้ plugin updater ของ Tauri เช็กวันละครั้งตอนเปิดโปรแกรม ผู้ใช้เลือกโหมดได้ อัตโนมัติ / แจ้งก่อน (ค่าเริ่มต้น) / ปิด
- คีย์เซ็นอัปเดตของ Tauri เก็บเป็น secret ใน GitHub Actions
- OMP และ Clink อัปเดตไปพร้อมกับตัวแอปเท่านั้น ห้ามดาวน์โหลดจากแหล่งอื่นระหว่างใช้งาน
- หลังอัปเดต:
  1. ติดตั้งโฟลเดอร์ runtime ของเวอร์ชันใหม่
  2. ใช้ธีมปัจจุบันซ้ำผ่านทรานแซกชัน เพื่อให้ AutoRun ชี้ไปที่ runtime ใหม่
  3. ลบโฟลเดอร์ runtime เก่าเมื่อไม่มีโปรเซสไหนล็อกไฟล์อยู่แล้ว
- ไฟล์ธีมรูปแบบเก่าจะถูกแปลงตาม §3.3

### 6.3 ถอนการติดตั้ง
- hook `NSIS_HOOK_PREUNINSTALL` เรียก `cmdstudio --cleanup` ก่อนลบไฟล์ ซึ่งทำตามลำดับนี้:
  1. เอาเฉพาะส่วนของเราออกจาก AutoRun (อ่านค่าแบบเดียวกับ planner) และเปิดคำสั่งของ Clink ตัวอื่นที่ CMD Studio ปิดไว้กลับคืน (phase 1b)
  2. คืนค่าโปรไฟล์ cmd ใน WT และลบ scheme ชื่อ `CMD Studio`
  3. ถอนฟอนต์ที่เราติดตั้ง · ไฟล์ฟอนต์ที่ WT ยังเปิดค้างอยู่จะลบไม่ได้ จึงบันทึกไว้ใน `state.json` แล้วลบตอนใช้ธีม ย้อนกลับ หรือย้อนทุกอย่างครั้งถัดไป หรือตอนรัน `--cleanup` ครั้งถัดไป (phase 1b)
  4. ลบข้อมูลของแอป ยกเว้น `themes\` ถ้าผู้ใช้ไม่ได้เลือกให้ลบ และลบ `%ProgramData%\ai.resincore.cmdstudio-<SID ของผู้ใช้>\` ถ้าเคยใช้ข้อ 3 ของ `<clink-launch>` (§5.4)
- `--cleanup` ใช้ล็อกเดียวกับการใช้ธีม (§5.5) และถ้ามีการเปลี่ยนแปลงที่ถูกตัดกลางทางแต่ยังตรวจไม่ได้ จะหยุดโดยไม่ลบอะไรเลย (`E_SNAPSHOT_READ`) เพราะจุดย้อนกลับนั้นอาจเป็นสำเนาเดียวของค่าเดิมของผู้ใช้ (phase 1b) · ถ้าตอนนี้อ่านบันทึกการย้อนกลับที่ไม่ครบ (`incomplete.json`) ไม่ได้ ก็จะหยุดโดยไม่เปลี่ยนและไม่ลบอะไรด้วย `E_SNAPSHOT_READ` เช่นกัน แล้วให้ลองใหม่ (§5.5, phase 1b)
- ถ้ายังไม่แน่ใจว่าทุกอย่างกลับเป็นเหมือนก่อนมี CMD Studio เช่น `state.json` เสียหรืออ่านไม่ได้, `settings.json` ที่แก้ไม่ได้จึงไม่ได้แตะ, ฟอนต์ที่ยังถอนไม่ได้, AutoRun ที่ต้องแก้ด้วยมือ, การย้อนกลับที่ไม่ครบ หรือจุดย้อนกลับที่ถูกกันไว้ต่างหากหรืออ่านไม่ได้ ข้อ 4 จะเก็บ `state.json` และจุดย้อนกลับไว้ เพราะเป็นบันทึกเดียวของค่าเดิม แล้วแจ้งเป็นขั้นที่ไม่สำเร็จพร้อมวิธีแก้ด้วยมือ รัน `--cleanup` ซ้ำกี่ครั้งก็ตรวจใหม่และได้คำตอบเดิม จนกว่าจะแก้ครบ (phase 1b)
- **hook นี้รันตอนอัปเดตด้วย** ✅ (G10) ต้องข้าม `--cleanup` เมื่อ `$UpdateMode = 1` ไม่อย่างนั้นการอัปเดตทุกครั้งจะย้อนธีมของผู้ใช้
- ตัวถอนของ Tauri มีช่องติ๊ก "ลบข้อมูลแอป" ช่องนี้คือตัวเลือก "ลบธีมของฉันด้วย" ตาม §2.1:
  - ถ้าติ๊ก (`$DeleteAppDataCheckboxState = 1`) ให้ส่ง `--remove-themes` แล้ว NSIS จะลบ `%LOCALAPPDATA%\ai.resincore.cmdstudio` เอง ✅ (G10)
- ปุ่ม "ย้อนทุกอย่าง" ในแอปทำข้อ 1–3 ได้โดยไม่ต้องถอนโปรแกรม
- ถ้า `--cleanup` ล้มเหลว ตัวถอนจะแสดงข้อความพร้อมรหัสปัญหา ส่วน guard `if exist` ใน AutoRun จะกันไม่ให้ cmd ขึ้น error หลังไฟล์ถูกลบ
- guard นี้กันได้แค่กรณีไฟล์หาย กรณี G19 ที่ไฟล์ยังอยู่แต่ Clink ล้มหลังเริ่มทำงาน guard กันไม่ได้ ✅ (เห็นจริงบน VM)

## 7. การทดสอบ

**ชนิดของเทสต์**
- **unit + snapshot test:** ครอบตัวสร้างไฟล์ทุกตัว
- **schema test:** มีไฟล์ตัวอย่างที่เป็นอันตรายครบทุกข้อใน §3.7
- **property test:** สุ่มสีหลัก × โทน × ค่าย้อม (0, 0.15, 0.30) อย่างน้อย 1,000 ชุด พาเลตที่ได้ต้องผ่านเกณฑ์ใน §3.4 ทุกชุด
- **parity test:** เทียบตัวจำลองพรีวิวกับ OMP ตัวจริงที่ pin ไว้ ครบทุก layout คูณทุก segment
- **integration test:** รันบน Windows runner โดยใช้โฟลเดอร์ WT ปลอมกับ HKCU จริงของ runner ซึ่งถูกทิ้งหลังรันเสร็จ ขั้นตอนคือใช้ธีม → ตรวจ → ย้อนกลับ แล้วสถานะต้องกลับมาเหมือนเดิมทุก byte
- **doctrine guard test** (กันกฎสำคัญถูกละเลยเงียบๆ):
  - (ก) `banner.lua` ไม่ทำอะไรตอนโหลด ทดสอบโดยโหลดใน Lua VM ที่ stub ฟังก์ชันไว้ แล้วต้องไม่มีอะไรพิมพ์ออกมา
  - (ข) config ของ OMP ที่สร้างไม่มี segment นอก whitelist
  - (ค) ตัวเขียน AutoRun ไม่เคยลบส่วนที่ไม่ใช่ของเรา
  - (ง) ย้อนกลับแล้ว `settings.json` เหมือนเดิมทุก byte

**ทดสอบแต่ละ tier ตั้งแต่เนิ่นๆ (Validate Every Target Tier Early)**

- เครื่องที่มี Clink ติดตั้งอยู่แล้ว
- path ที่มีอักษรไทยหรือช่องว่าง (G17 ✅ สำหรับ OMP, G19 ❌ สำหรับไฟล์ของ Clink เอง)
- output ของ OMP ตัวจริงเทียบกับตัวจำลอง
- หัวข้อความของ cmd บน Windows ภาษาไทย ✅ (G4: เป็นภาษาอังกฤษ แต่ต้องคงเทสต์ไว้เผื่อ Windows รุ่นหน้าแปลหัวข้อความ)

   ปัญหาคือ Clink inject ไม่ได้จาก path ที่มีชื่อผู้ใช้ภาษาไทย ทั้งบน Windows ภาษาไทยและภาษาอังกฤษ ถ้าเลือกผิด ผู้ใช้ที่ชื่อเป็นภาษาไทยจะเห็น error ใน cmd ทุกหน้าต่าง ทั้ง (ก) และ (ข) ลองแล้วว่าใช้ได้บนทั้ง 2 แบบ:

     - ข้อเสีย: ชื่อแบบ 8.3 ถูกปิดได้ทีละ volume
   - (ข) **โฟลเดอร์ที่ไม่มีชื่อผู้ใช้:** วาง runtime ของ Clink ไว้ใต้ `C:\ProgramData`
     - ข้อดี: ไม่พึ่ง 8.3
     - ข้อเสีย: แอปที่ติดตั้งรายผู้ใช้ต้องเขียนนอกโฟลเดอร์ของผู้ใช้ และต้องคิดกรณีเครื่องที่มีหลายผู้ใช้ (คิดแล้วเมื่อ 2026-10-11 ดูข้อ 3 ของ `<clink-launch>` ใน §5.4)
   - (ค) **แจ้ง upstream:** ส่งรายงานบั๊กให้ Clink ซึ่งเคยแก้อาการเดียวกันกับ path ภาษาจีนใน issue #203 เมื่อปี 2021 แต่เป็นการโพสต์สาธารณะ จึงต้องให้ founder อนุมัติ
